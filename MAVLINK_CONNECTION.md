# Подключение через MAVLink UDP

## Проблема

После изменения сетевой схемы (Raspberry Pi и компьютер подключены к одной точке Wi-Fi вместо того, чтобы Raspberry Pi раздавал Wi-Fi) подключение через Mission Planner не работает.

## Как работает MAVLink UDP в проекте

### Архитектура подключения

1. **UDP адаптер** (`adapters.js`):
   - Слушает на порту `14550` (по умолчанию) на всех интерфейсах (`0.0.0.0`)
   - Работает в режиме "ответ на запрос":
     - Запоминает адрес первого отправителя
     - Отправляет ответы только на этот адрес
   - Это означает, что Mission Planner должен **первым** отправить запрос на Raspberry Pi

2. **Настройки** (переменные окружения):
   - `MAVLINK_UDP_EN=true` - **обязательно** должно быть включено
   - `MAVLINK_UDP_HOST=0.0.0.0` - слушать на всех интерфейсах (по умолчанию)
   - `MAVLINK_UDP_PORT=14550` - порт UDP (по умолчанию)

### Определение IP адреса Raspberry Pi

IP адрес определяется автоматически из интерфейса `wlan0` и выводится в логи:
```
[drone]: ip changed 192.168.1.100
[status]: false (192.168.1.100)
```

Также IP адрес можно узнать:
1. **Через логи** - при запуске системы выводится сообщение `[drone]: ip changed <IP>`
2. **Через веб-интерфейс** - откройте `http://<IP_RASPBERRY>:8080` (IP будет виден в адресной строке)
3. **Через SSH** - выполните `hostname -I` или `ip addr show wlan0`

## Решение проблемы

### Шаг 1: Проверьте настройки .env

Убедитесь, что в файле `.env` включен UDP:

```env
MAVLINK_UDP_EN=true
MAVLINK_UDP_HOST=0.0.0.0
MAVLINK_UDP_PORT=14550
```

### Шаг 2: Узнайте IP адрес Raspberry Pi

После запуска системы (`node index.js`) в логах будет выведен IP адрес:
```
[drone]: ip changed 192.168.1.100
[mavlink-udp]: 0.0.0.0:14550 > unknown
```

Когда Mission Planner подключится, появится сообщение:
```
[mavlink-udp]: 0.0.0.0:14550 > 192.168.1.50:14550
```

### Шаг 3: Настройте Mission Planner

1. Откройте Mission Planner
2. Перейдите в **Settings** → **Comms**
3. Выберите тип подключения: **UDP**
4. Укажите:
   - **Host**: IP адрес Raspberry Pi (например, `192.168.1.100`)
   - **Port**: `14550`
5. Нажмите **Connect**

### Шаг 4: Проверьте подключение

После подключения в логах Raspberry Pi должно появиться:
```
[mavlink-udp]: 0.0.0.0:14550 > <IP_КОМПЬЮТЕРА>:14550
```

## Возможные проблемы

### Проблема: Mission Planner не подключается

**Причины:**
1. UDP не включен (`MAVLINK_UDP_EN=false` или отсутствует)
2. Неправильный IP адрес в Mission Planner
3. Файрвол блокирует порт 14550
4. Raspberry Pi и компьютер в разных подсетях

**Решение:**
1. Проверьте `.env` файл - должно быть `MAVLINK_UDP_EN=true`
2. Убедитесь, что IP адрес правильный (проверьте логи)
3. Проверьте файрвол: `sudo ufw status` (если включен, разрешите порт: `sudo ufw allow 14550/udp`)
4. Убедитесь, что оба устройства в одной сети (проверьте первые 3 октета IP адресов)

### Проблема: Подключение работает, но данные не передаются

**Причина:** UDP адаптер работает в режиме "ответ на запрос" - если Mission Planner не отправляет первое сообщение, соединение не устанавливается.

**Решение:** Mission Planner должен автоматически отправлять heartbeat при подключении. Если проблема сохраняется, попробуйте переподключиться.

## Альтернативное решение: Широковещательный режим

Если текущий режим не работает, можно изменить UDP адаптер для работы в широковещательном режиме (требует изменения кода). В этом случае Raspberry Pi будет отправлять данные на широковещательный адрес, и Mission Planner сможет подключиться без указания IP адреса.
